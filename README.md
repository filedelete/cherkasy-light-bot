# Бот графіка відключень: Черкаська область

Кожні 10 хвилин перевіряє сайт Черкасиобленерго й постить у Telegram-канал (або групу) текстове повідомлення з графіком усіх черг, коли графік **з'явився** або **змінився**. Для кожної черги видно години без світла й скільки це разом; якщо графік змінився, зверху показано, які черги змінились і що саме (➖ було, ➕ стало), а ці черги позначено 🔄.
Кожне таке повідомлення бот одразу **закріплює**, а попереднє закріплене відкріплює (вимкнути: змінна `PIN_MESSAGE: "0"` у `check.yml`). Працює безкоштовно на GitHub Actions. Дані бере через бібліотеку [ukraine-energy-monitor](https://github.com/fastiuk/ukraine-energy-monitor).

## Налаштування (≈15 хв)

1. **Бот.** У Telegram відкрийте @BotFather → `/newbot` → збережіть **токен**.
2. **Канал.** Створіть канал (або групу), додайте бота **адміністратором** з правами **публікувати повідомлення** і **закріплювати повідомлення**.
3. **chat_id.**
   - Публічний канал: підійде `@назва_каналу`.
   - Приватний канал чи група: перешліть будь-яке повідомлення з нього боту @getidsbot і візьміть число виду `-100…`.
4. **Репозиторій.** На GitHub створіть репозиторій (публічний дає більше безкоштовних хвилин) і завантажте туди **весь вміст цієї папки**, зокрема прихованої папки `.github`.
5. **Secrets.** Repo → Settings → Secrets and variables → Actions → New repository secret:
   - `TELEGRAM_BOT_TOKEN`: токен із кроку 1;
   - `TELEGRAM_CHAT_ID`: з кроку 3 (кілька чатів через кому);
   - `ADMIN_CHAT_ID` (необов'язково, але рекомендовано): ваш особистий chat_id (дізнатись у @getidsbot; бота треба спершу запустити кнопкою Start). Бот писатиме вам у приват: щодня близько 8:00 «✅ Бот працює нормально» зі статистикою, коротку нотатку після кожної публікації в канал (вимкнути: `ADMIN_NOTES: "0"` у `check.yml`), а при збої, який триває понад ≈30 хвилин, пояснення, що сталося, посилання на журнал запуску і кроки, що робити; коли все відновиться, напише ще раз. Якщо щоденного звіту немає, бот не запускається: відкрийте вкладку Actions.
6. **Запуск.** Вкладка Actions → `check-schedule` → Run workflow. Далі він запускається сам.

Перший запуск публікує поточні графіки. Щоб цього не було, додайте в `check.yml` змінну `POST_ON_FIRST_RUN: "0"`.

## Сайт (GitHub Pages)

Разом із постами в Telegram бот оновлює сторінку `docs/index.html`: графік на сьогодні й завтра, вибір своєї черги (запам'ятовується в браузері) і статус «зараз світло є / немає, наступна зміна о…», який сторінка рахує сама за київським часом.

Увімкнути (один раз): репозиторій → **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, папка `/docs` → Save**. Адреса сайту з'явиться на цій сторінці за 1–2 хвилини, зазвичай `https://ІМ'Я.github.io/НАЗВА-РЕПОЗИТОРІЮ/`. Сторінка з'являється після першого запуску бота. Під повідомленнями бота й закріпленим постом з'являється кнопка «🌐 Відкрити сайт»: адреса береться з назви репозиторію автоматично (інша адреса, наприклад власний домен, задається змінною `SITE_URL` у `check.yml`). Вимкнути сайт і кнопку: змінна `SITE: "0"` у `check.yml`.

### Додаткові функції

- **Календар для кожної черги** (`docs/cal/1-1.ics` …): на сайті, у вибраній черзі, кнопки «Підписатись» / «Завантажити .ics». Кожне відключення стає подією з нагадуванням за 15 хвилин. Apple Календар і Outlook підтягують оновлення швидко й показують нагадування; Google Календар оновлює підписки раз на 12–24 години й нагадування з підписаних календарів не показує. Для нього краще імпортувати файл .ics.
- **Пряме посилання на чергу:** `https://…/?q=3.1` одразу відкриває потрібну чергу; кнопка «Поділитись» на сайті копіює таке посилання.
- **Підсумок тижня:** щонеділі з 20:00 бот публікує в канал рейтинг черг за годинами без світла, середнє по області й найдовше відключення поспіль. Потрібно щонайменше 3 дні накопичених даних, тож перший підсумок з'явиться наприкінці першого повного тижня роботи. Рахується за графіком, аварійні відключення не враховано.

## Перевірка без Telegram

```
pip install -r requirements.txt          # потрібен Python 3.13
python -m bot.demo                       # друкує приклади повідомлень і створює out/index.html (сайт)
DRY_RUN=1 python -m bot.main             # справжній запит до сайту, але нічого не відправляє
```

## Якщо сайт обленерго не відкривається з GitHub

У логу Actions буде `Не вдалося отримати графік…`. Тоді запустіть той самий код на постійно ввімкненому пристрої в Україні (комп'ютер, Raspberry Pi, VPS): задайте ті самі змінні середовища й додайте в cron `*/10 * * * * cd /шлях && python -m bot.main`. Стан зберігається у `state/state.json`.

## Нотатки

- GitHub може запускати розклад із затримкою в кілька хвилин. Сповіщення це не втрачає: порівнюється з попереднім станом.
- Раз на добу бот оновлює `state/state.json`, щоб GitHub не вимкнув розклад через 60 днів без активності.
- Графіки належать операторам системи розподілу.
